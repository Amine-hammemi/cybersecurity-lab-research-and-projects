# Windows Event Logs

> My notes on Windows logging and how I use event records to understand endpoint activity.

## 1. What are Windows Event Logs?

- Windows records system and application activity as events.
- Events are organized into **logs** and **channels**.
- An event usually contains a timestamp, provider, Event ID, level and event-specific data.
- Event logs help administrators troubleshoot systems and help security analysts investigate activity.

## 2. Common Windows logs

| Log         | Typical content                                              |
| ----------- | ------------------------------------------------------------ |
| Application | Events generated by applications                             |
| Security    | Auditing events such as logons and security-related activity |
| System      | Events generated by Windows components and drivers           |
| Setup       | Operating system setup and update events                     |

There are also application-specific and operational channels, such as:

```text
Microsoft-Windows-Sysmon/Operational
```

## 3. Event Viewer

I can open Event Viewer using:

```text
eventvwr.msc
```

Useful areas:

- Windows Logs → Application
- Windows Logs → Security
- Windows Logs → System
- Applications and Services Logs → Microsoft → Windows

When investigating an event, I should inspect:

1. Timestamp.
2. Provider/source.
3. Event ID.
4. Level.
5. User or account, if present.
6. Computer name.
7. Event-specific details.
8. Related events before and after it.

## 4. Event ID: what does it mean?

- An Event ID identifies an event type from a particular provider.
- An Event ID must be interpreted together with its provider and channel.
- The same numeric Event ID can mean different things for different providers.

Do not interpret an Event ID without checking its source and event details.

## 5. Useful PowerShell commands

List available event logs:

```powershell
Get-WinEvent -ListLog *
```

Read recent System events:

```powershell
Get-WinEvent -LogName System -MaxEvents 20
```

Read recent Sysmon events:

```powershell
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 20
```

Filter by a specific Event ID:

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = "Microsoft-Windows-Sysmon/Operational"
    Id = 1
} -MaxEvents 10
```

## 6. Windows Event Logs vs Sysmon

- Windows Event Logs are the general Windows logging infrastructure.
- Sysmon is an additional monitoring component that generates detailed security telemetry.
- Sysmon writes its events to the `Microsoft-Windows-Sysmon/Operational` channel.
- A SIEM such as Wazuh can collect selected channels.

See [Sysmon](Sysmon.md) for Sysmon's event types and configuration.

## 7. Log retention and collection

- Windows event channels have configured maximum sizes and retention behaviour.
- When a log reaches its configured limit, older events may be overwritten depending on its settings.
- A SIEM can provide centralized storage, but only for data that is actually collected and successfully forwarded.
- More telemetry increases storage and processing requirements.
